# v0.1 Release Baseline

- Status: Closed
- Date: 2026-04-20

This document is the operator-facing closure note for Catalyst Continuum `v0.1`. The detailed
release boundary lives in [v0.1-scope.md](v0.1-scope.md).

## Shipped In v0.1

### Core Orchestration

- Structured brief intake, validation, and deterministic pack resolution.
- Durable run, task, artifact, and run-event state in Postgres.
- Pack-driven repository generation for the baseline service, CLI, and worker packs.
- Durable artifact pipeline for backlog, dispatch, policy, quality, workspace snapshot, PR
  candidate, developer handoff, PR export, publication, and GitHub PR artifacts.
- Offline developer session generation for `brief.json`, self-contained Codex/Cursor/OpenHands
  prompts, validation commands, and a human runbook before a developer commits to a full
  orchestration run. Each prompt embeds the brief-derived goals, functional requirements,
  acceptance criteria, constraints, deliverables, policy limits, validation commands, and expected
  delivery report.
- Release-facing alpha guide through `make start` and `make alpha-guide`, which prints the shortest
  solo-developer value path instead of forcing new users to read the full command catalog first.
- Read-only alpha readiness report through `make alpha-readiness`, which summarizes local checkout
  cleanliness, required release docs/scripts, PR state, and latest GitHub Actions status before a
  maintainer cuts or announces an alpha.
- GitHub issue session generation through `make github-issue-session`, which imports issues or
  offline issue fixtures into the same native-agent package and marks issue text as untrusted
  repository context. The importer supports `per-issue` PR packaging for one PR per task and
  `batch` PR packaging for one aggregate session that keeps a related issue set in one PR.
- Step-by-step GitHub issue selection through `make github-issue-next`, which ranks an imported
  issue batch, creates only the top recommended session, and writes `issue-batch.json` plus
  `issue-batch.md` for review.
- One-command GitHub issue work-package execution through `make github-issue-run`, which composes
  issue import, session creation, local Docker-backed execution, PR export evidence, and a GitHub
  issue sync dry-run plan without duplicating the underlying command logic. The same wrapper can
  explicitly continue to repository-target controlled GitHub draft PR creation with
  `GITHUB_ISSUE_CREATE_DRAFT_PR=1` and attach the resulting PR URL to the issue evidence. The
  wrapper writes `workflow-report.md` beside `workflow-summary.json` so a developer can read the
  outcome, evidence, PR handoff, and next step without parsing JSON. The paired
  `make github-issue-plan` entrypoint creates the selected session and local workflow plan without
  running agents or mutating GitHub, including readable issue details and generated agent handoff
  paths when they are present in the selected session.
- GitHub issue status sync through `make github-issue-sync`, which comments source issues with run
  evidence, attaches branch/commit/PR details, applies Catalyst labels, supports `in-progress`
  claim plans, records failed execution attempts with `continuum:failed`, and can explicitly close
  issue-derived work as completed when `GITHUB_ISSUE_SYNC_STATUS=done` is requested.
- One-command solo developer run entrypoint through `make dev-run`, which creates a daily-task
  brief, submits it, executes Docker-backed tasks, evaluates policy and quality, exports a local PR
  candidate, and generates `developer_handoff` without pushing to GitHub.
- Existing session brief execution through `make dev-run-brief`, so a developer can create one
  `brief.json`, hand it to Codex/Cursor/OpenHands, and later run that exact input through the
  orchestrator without retyping task context.
- Latest-session execution through `make dev-run-latest-session`, so the common session-to-run path
  does not require copying a generated path from terminal output.
- Developer artifact discovery through `make dev-latest`, including a recommended next action for
  the newest session, brief, or run, plus `make dev-session-review`, `make dev-agent-prompt`,
  `make dev-agent-prompt-path`, `make dev-agent-prompt-command`, and
  `make dev-agent-prompt-copy` for focused session handoff, direct Codex, Cursor, or OpenHands
  prompt retrieval, exact continuation commands, and clipboard handoff from the latest or selected
  `.continuum/dev-sessions/` package.
- GitHub issue workflow discovery through `make github-issue-latest`,
  `make github-issue-plan-review`, `make github-issue-preflight`,
  `make github-issue-preflight-strict`, `make github-issue-review`,
  `make github-issue-next-command`, `make github-issue-sync-command`,
  `make github-issue-agent-prompt`, `make github-issue-agent-prompt-path`, and
  `make github-issue-agent-prompt-command`, and `make github-issue-agent-prompt-copy`, including
  readable report lookup, selected issue refs and recorded issue details, focused plan handoff,
  read-only preflight execution, embedded review commands, command-only continuation, reviewed
  issue-sync apply command generation, source-issue links, generated issue-sync comment
  preview/copy in the Operator UI, and direct Codex, Cursor, or OpenHands prompt retrieval or
  clipboard copy from the latest or selected report/plan
  `.continuum/github-issue-workflows/` output directory.
- Focused next-action output through `make dev-next` and command-only output through
  `make dev-next-command`.
- Focused pre-run session output through `make dev-session-review`, including the selected session
  manifest, checkout state, brief, runbook, prompts, validation commands, and matching
  `dev-run-brief` command.
- Focused review-stage output through `make dev-review`, including the latest review package, agent
  prompt, local PR export paths, and local diff inspection commands.
- Orchestrator-owned run guidance through `make run-guide`, HTTP `GET /runs/{run_id}/guide`, and
  MCP `describe_run_guide`, so developers and agents can ask for the next safe action directly.
- Developer handoff generation for readable review notes, reusable agent prompts, and structured
  evidence manifests.
- HTTP, CLI, and MCP surfaces over the same Rust command layer.

### Runtime And Agents

- Docker-first runtime-provider execution with enforced task timeouts, named and labelled
  disposable containers, applied network-mode settings, explicit restricted-sandbox flags, and
  best-effort non-root user mapping.
- Worker control loop plus external-agent claim, heartbeat, workspace handoff, and completion flow.
- Pinned OpenHands launch profiles for host-process and Docker-sandbox sessions, with repo-local
  persistence, rendered MCP config, CI-safe executor contract smoke, and opt-in live real-agent
  smoke for local LiteLLM/OpenHands validation.
- Codex app-server bridge for generated Catalyst prompts, including standalone app-server evidence
  mode, optional proxy mode for a running Codex Desktop or IDE app-server control socket, and
  persisted thread/turn manifest, JSONL events, client messages, and stderr diagnostics. Developer
  handoff artifacts also expose Codex app-server commands for their persisted review prompt, and the
  operator UI renders those commands in the Developer tab.
- External MCP capability-policy contract, upstream `Everything` interoperability checks, and
  documented `Fetch` guidance.

### Operator UI

The built-in operator UI is served by the orchestrator at `/ui` over the same HTTP control-plane
surface.

It includes:

- First-screen product explanation for the brief-to-run-to-quality-to-draft-PR lifecycle.
- Manual brief-driven flow separated from optional webhook or repository-signal automation.
- Mission Control tabs for `Flow`, `Developer`, `Agents`, `Grafana`, and `LiteLLM`.
- Live badges for selected-run status, agent count, Grafana readiness, and LiteLLM gateway/UI state.
- Run journey timeline, guarded recommended action strip, control readiness board, review handoff
  checklist, and evidence map.
- Developer handoff control that packages the selected run into `review.md`,
  `agent-review-prompt.md`, and `manifest.json`.
- Solo-developer demo entrypoint that seeds one complete local delivery run and opens the UI against
  that state without requiring GitHub publication credentials.
- Agent handoff map, multi-agent lanes, persisted `agent_task_report` details, runtime `log`
  artifacts, bounded stdout/stderr context with truncation indicators, and linked
  `task_workspace_input` handoff artifacts.
- Embedded Grafana and LiteLLM surfaces so the operator can stay inside one UI shell.
- Automation queue controls for webhook advancement and repository-signal materialization.
- Repository-target publication posture summaries, including the local-export-only blocked state.
- Summary-first response panes, guided empty states, starter-brief scenario cards, and responsive
  task/artifact cards for mobile-friendly sessions.
- WebSocket-first live updates through `/ui/ws`, explicit manual refresh fallback, change-aware
  in-place refresh, preserved selected-run context, stable focus behavior, and no expected hard
  reloads during normal interaction.

### GitHub And Publication

- Signed GitHub webhook intake and durable repository-signal handoff.
- Draft-PR promotion flow with GitHub App API publication when outbound App credentials are
  configured.
- `gh` fallback only when GitHub App publication credentials are absent.
- Opt-in repository-target enforcement for real GitHub publication.
- `repository_target_id` based promotion defaults for CLI, HTTP, MCP, and the operator UI.
- Non-mutating `repository-targets-init` and `repository-targets-bootstrap` helpers for local
  allowlist bootstrap and readiness proof.
- Redis-backed short-lived coordination for run-scoped publication locks across CLI, HTTP, and MCP.

### LiteLLM And Observability

- Redis-backed LiteLLM proxy caching for local agent validation traffic.
- Shared local Postgres persistence for the bundled LiteLLM proxy.
- LiteLLM OpenTelemetry export into the local collector for gateway traces and semantic log events.
- LiteLLM AI edge-gateway boundary, while the orchestrator remains authoritative for run policy,
  runtime control, and publication lineage.
- Machine-readable AI gateway contract through `config/ai-gateway.yaml` and
  `describe_instance_config`.
- OpenTelemetry baseline with Collector, Prometheus, Tempo, Loki, and Grafana in the local stack.

## Closed v0.1 Local Stack

The shipped local compose baseline for `v0.1` is:

- orchestrator
- worker
- litellm
- postgres
- redis
- otel-collector
- prometheus
- tempo
- loki
- grafana

`LiteLLM` is a required bundled service in the closed `v0.1` compose baseline.

Local model backend policy:

- macOS Apple Silicon prefers native `mlx-lm`.
- Other developer platforms prefer Ollama.
- macOS can still opt into Ollama when desired.
- macOS-native examples use a coding-tuned MLX model by default.

LiteLLM compose behavior:

- The proxy keeps Redis-backed cache entries in the local stack.
- The proxy uses the shared local Postgres server through a dedicated LiteLLM database.
- LiteLLM is the AI edge gateway for model routing, gateway state, and gateway telemetry.
- Future search, vector-store, RAG, or A2A-compatible remote-agent edge work should extend that
  gateway layer instead of introducing a second mutable control plane beside the Rust orchestrator.

Compose runtime behavior:

- `orchestrator` and `worker` share one artifact volume.
- The container image carries `config/runtime-providers.yaml` and `config/mcp-servers.yaml`.
- `prometheus`, `grafana`, and `orchestrator` expose healthchecks.
- The long-lived `worker` waits for a healthy `orchestrator` before starting.
- Shared schema bootstrap is serialized with a Postgres advisory transaction lock.
- Containerized live gateway checks use `CATALYST_AI_GATEWAY_STATUS_BASE_URL=http://litellm:4000`.

## Explicitly Not In v0.1

- Proxmox runtime-provider support
- Kubernetes runtime-provider support
- orchestrator-managed third-party MCP sidecar lifecycle
- generic MCP marketplace behavior
- duplication of native agent capabilities such as `git` or local filesystem access

## Validation Baseline

The release baseline should continue to pass these repository-standard checks:

- `make release-check`
- `make alpha-readiness`
- `./scripts/check-versions.sh`
- `./scripts/check-markdown-links.sh`
- `./scripts/doctor.sh`
- `./scripts/lint-operator-ui-assets.sh`
- `./scripts/repository-target-bootstrap-smoke.sh`
- `./scripts/check-template-repo.sh`
- `./scripts/ci-compose.sh`
- `./scripts/compose-runtime-check.sh`
- `./scripts/compose-observability-smoke.sh --no-build`
- `./scripts/eval-baseline.sh`
- `./scripts/ci-rust.sh`
- `./scripts/ci-smoke.sh`
- `make solo-demo-check`
- `./scripts/operator-ui-smoke.sh`
- `./scripts/openhands-run-agent-task-smoke.sh`
- `./scripts/codex-app-server-run-smoke.sh`
- `make ui-smoke-repository-policy`
- `make ui-smoke-repository-policy-blocked`

`make release-check` is the canonical local aggregate for this list. It intentionally builds on
`make ci`, then adds the release-only doctor and operator UI repository-policy postures so the
operator path matches the published baseline.

The GitHub Actions `shell` job also protects local Markdown links so docs cannot drift into broken
relative links, repository-escaping links, or machine-specific absolute local paths.

The GitHub Actions `shell` job also protects the alpha guide smoke, so first-user release guidance
and read-only readiness output cannot silently drift from the documented alpha path.

The GitHub Actions `ui` matrix protects the default operator UI smoke plus both repository-policy
UI postures so these browser-level checks are not manual-only release criteria.

The GitHub Actions `rust` job also runs `./scripts/doctor.sh --no-live` after the Rust build/test
path, so the release-baseline doctor check verifies pinned tools, config files, compose rendering,
and instance-config parsing in CI without depending on live local services.

`./scripts/openhands-run-agent-task-smoke.sh` is the CI-safe OpenHands executor contract check. For
live local validation with the real pinned OpenHands launcher, run
`OPENHANDS_REAL_AGENT_SMOKE=1 make openhands-agent-task-real-smoke` after LiteLLM and a coding model
are reachable.

`./scripts/codex-app-server-run-smoke.sh` is the CI-safe Codex app-server bridge contract check. It
uses a fake Codex app-server to prove the protocol wrapper and evidence files. Live Codex UI
attachment remains an operator environment check because it depends on a running Codex Desktop or
IDE app-server control socket.

On Apple Silicon, `act` remains useful for workflow-shape checks, but full Rust execution under
`act` can still hit the known upstream `qemu`/`rustc` crash path.
