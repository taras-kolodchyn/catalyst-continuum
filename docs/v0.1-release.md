# v0.1 Release Baseline

- Status: Closed
- Date: 2026-04-20

This document is the operator-facing closure note for Catalyst Continuum `v0.1`. The detailed
release boundary lives in [v0.1-scope.md](v0.1-scope.md).

## Shipped In v0.1

### Core Orchestration

- Structured brief intake, validation, and deterministic pack resolution.
- Durable run, task, artifact, and run-event state in Postgres.
- Pack-driven repository generation for the baseline service, CLI, and worker packs.
- Durable artifact pipeline for backlog, dispatch, policy, quality, workspace snapshot, PR
  candidate, PR export, publication, and GitHub PR artifacts.
- HTTP, CLI, and MCP surfaces over the same Rust command layer.

### Runtime And Agents

- Docker-first runtime-provider execution with enforced task timeouts, named and labelled
  disposable containers, applied network-mode settings, explicit restricted-sandbox flags, and
  best-effort non-root user mapping.
- Worker control loop plus external-agent claim, heartbeat, workspace handoff, and completion flow.
- Pinned OpenHands launch profiles for host-process and Docker-sandbox sessions, with repo-local
  persistence, rendered MCP config, CI-safe executor contract smoke, and opt-in live real-agent
  smoke for local LiteLLM/OpenHands validation.
- External MCP capability-policy contract, upstream `Everything` interoperability checks, and
  documented `Fetch` guidance.

### Operator UI

The built-in operator UI is served by the orchestrator at `/ui` over the same HTTP control-plane
surface.

It includes:

- First-screen product explanation for the brief-to-run-to-quality-to-draft-PR lifecycle.
- Manual brief-driven flow separated from optional webhook or repository-signal automation.
- Mission Control tabs for `Flow`, `Agents`, `Grafana`, and `LiteLLM`.
- Live badges for selected-run status, agent count, Grafana readiness, and LiteLLM gateway/UI state.
- Run journey timeline, guarded recommended action strip, control readiness board, review handoff
  checklist, and evidence map.
- Agent handoff map, multi-agent lanes, persisted `agent_task_report` details, runtime `log`
  artifacts, bounded stdout/stderr context with truncation indicators, and linked
  `task_workspace_input` handoff artifacts.
- Embedded Grafana and LiteLLM surfaces so the operator can stay inside one UI shell.
- Automation queue controls for webhook advancement and repository-signal materialization.
- Repository-target publication posture summaries, including the local-export-only blocked state.
- Summary-first response panes, guided empty states, starter-brief scenario cards, and responsive
  task/artifact cards for mobile-friendly sessions.
- WebSocket-first live updates through `/ui/ws`, explicit manual refresh fallback, change-aware
  in-place refresh, preserved selected-run context, stable focus behavior, and no expected hard
  reloads during normal interaction.

### GitHub And Publication

- Signed GitHub webhook intake and durable repository-signal handoff.
- Draft-PR promotion flow with GitHub App API publication when outbound App credentials are
  configured.
- `gh` fallback only when GitHub App publication credentials are absent.
- Opt-in repository-target enforcement for real GitHub publication.
- `repository_target_id` based promotion defaults for CLI, HTTP, MCP, and the operator UI.
- Non-mutating `repository-targets-init` and `repository-targets-bootstrap` helpers for local
  allowlist bootstrap and readiness proof.
- Redis-backed short-lived coordination for run-scoped publication locks across CLI, HTTP, and MCP.

### LiteLLM And Observability

- Redis-backed LiteLLM proxy caching for local agent validation traffic.
- Shared local Postgres persistence for the bundled LiteLLM proxy.
- LiteLLM OpenTelemetry export into the local collector for gateway traces and semantic log events.
- LiteLLM AI edge-gateway boundary, while the orchestrator remains authoritative for run policy,
  runtime control, and publication lineage.
- Machine-readable AI gateway contract through `config/ai-gateway.yaml` and
  `describe_instance_config`.
- OpenTelemetry baseline with Collector, Prometheus, Tempo, Loki, and Grafana in the local stack.

### Release Guardrails

- Baseline evaluation coverage through `./scripts/eval-baseline.sh`.
- Published persisted artifact schemas plus a shared run-event taxonomy registry.
- Template repository scaffolding for private-instance follow-on work.

## Closed v0.1 Local Stack

The shipped local compose baseline for `v0.1` is:

- orchestrator
- worker
- litellm
- postgres
- redis
- otel-collector
- prometheus
- tempo
- loki
- grafana

`LiteLLM` is a required bundled service in the closed `v0.1` compose baseline.

Local model backend policy:

- macOS Apple Silicon prefers native `mlx-lm`.
- Other developer platforms prefer Ollama.
- macOS can still opt into Ollama when desired.
- macOS-native examples use a coding-tuned MLX model by default.

LiteLLM compose behavior:

- The proxy keeps Redis-backed cache entries in the local stack.
- The proxy uses the shared local Postgres server through a dedicated LiteLLM database.
- LiteLLM is the AI edge gateway for model routing, gateway state, and gateway telemetry.
- Future search, vector-store, RAG, or A2A-compatible remote-agent edge work should extend that
  gateway layer instead of introducing a second mutable control plane beside the Rust orchestrator.

Compose runtime behavior:

- `orchestrator` and `worker` share one artifact volume.
- The container image carries `config/runtime-providers.yaml` and `config/mcp-servers.yaml`.
- `prometheus`, `grafana`, and `orchestrator` expose healthchecks.
- The long-lived `worker` waits for a healthy `orchestrator` before starting.
- Shared schema bootstrap is serialized with a Postgres advisory transaction lock.
- Containerized live gateway checks use `CATALYST_AI_GATEWAY_STATUS_BASE_URL=http://litellm:4000`.

## Explicitly Not In v0.1

- Proxmox runtime-provider support
- Kubernetes runtime-provider support
- orchestrator-managed third-party MCP sidecar lifecycle
- generic MCP marketplace behavior
- duplication of native agent capabilities such as `git` or local filesystem access

## Validation Baseline

The release baseline should continue to pass these repository-standard checks:

- `make release-check`
- `./scripts/check-versions.sh`
- `./scripts/doctor.sh`
- `./scripts/repository-target-bootstrap-smoke.sh`
- `./scripts/check-template-repo.sh`
- `./scripts/ci-compose.sh`
- `./scripts/compose-runtime-check.sh`
- `./scripts/compose-observability-smoke.sh --no-build`
- `./scripts/eval-baseline.sh`
- `./scripts/ci-rust.sh`
- `./scripts/ci-smoke.sh`
- `./scripts/operator-ui-smoke.sh`
- `./scripts/openhands-run-agent-task-smoke.sh`
- `make ui-smoke-repository-policy`
- `make ui-smoke-repository-policy-blocked`

`make release-check` is the canonical local aggregate for this list. It intentionally builds on
`make ci`, then adds the release-only doctor and operator UI repository-policy postures so the
operator path matches the published baseline.

The GitHub Actions `ui` matrix protects the default operator UI smoke plus both repository-policy
UI postures so these browser-level checks are not manual-only release criteria.

The GitHub Actions `rust` job also runs `./scripts/doctor.sh --no-live` after the Rust build/test
path, so the release-baseline doctor check verifies pinned tools, config files, compose rendering,
and instance-config parsing in CI without depending on live local services.

`./scripts/openhands-run-agent-task-smoke.sh` is the CI-safe OpenHands executor contract check. For
live local validation with the real pinned OpenHands launcher, run
`OPENHANDS_REAL_AGENT_SMOKE=1 make openhands-agent-task-real-smoke` after LiteLLM and a coding model
are reachable.

On Apple Silicon, `act` remains useful for workflow-shape checks, but full Rust execution under
`act` can still hit the known upstream `qemu`/`rustc` crash path.
