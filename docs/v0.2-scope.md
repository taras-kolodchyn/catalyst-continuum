# v0.2 Scope

This document defines the planned cut line for Catalyst Continuum `v0.2`.

The rule behind this scope is strict:

- `v0.2` should deepen contracts, interoperability, and operator ergonomics without turning the orchestrator into a duplicate agent framework
- third-party MCP servers should remain agent- or operator-managed unless the control plane can add clear policy, audit, reproducibility, or observability value

## Planned For v0.2

- `Declarative external MCP server contract`
  Packs should be able to declare recommended external MCP servers, their purpose, and any setup hints an agent or operator needs to attach them.
  This is descriptive contract data first. `v0.2` should not make the orchestrator responsible for launching or supervising arbitrary third-party MCP sidecars.

- `Reference MCP interoperability checks`
  Add local and CI coverage against upstream reference MCP servers so compatibility is not inferred only from our own smoke scripts.
  The first fixture should be the upstream `Everything` server because it exercises the broadest reference surface for tools, resources, and prompts.

- `Documented Fetch integration`
  Treat upstream `Fetch` as the first recommended external MCP server.
  It is a good first candidate because it adds useful web retrieval capability without duplicating the core coding, git, or local filesystem abilities that OpenHands and Codex already provide natively.

- `Published artifact schemas`
  Make the key persisted artifact contracts explicit and inspectable.
  The first published schema set should cover at least `backlog`, `agent_dispatch_plan`, `policy_report`, `quality_report`, `agent_task_report`, `pr_candidate`, and `pr_export`.

- `Structured event model hardening`
  Tighten and document the durable run-event taxonomy so operators, MCP clients, and future UIs can reason over the same event contract instead of parsing log text.

- `Repository pack contract hardening`
  Keep turning packs into the canonical source for template selection, supported agents, smoke contracts, and external MCP recommendations.
  Pack docs and examples should stay aligned with the contract.

- `Template repository and private deployment flow`
  Separate public upstream code from private deployment-specific configuration more cleanly, while keeping local Docker validation and later Proxmox/Kubernetes evolution in view.

- `Deeper GitHub App integration`
  Expand beyond signed ingress and safe default-branch sync into a cleaner repository automation path that still preserves explicit control-plane state and publication gates.

- `Basic evaluation coverage`
  Add a small but real evaluation layer for brief validation, pack selection, artifact generation, and safe promotion decisions.

## Explicitly Out Of Scope For v0.2

- `Orchestrator-managed third-party MCP sidecar lifecycle`
  Do not turn the orchestrator into a generic launcher or supervisor for arbitrary external MCP servers yet.

- `Generic MCP marketplace behavior`
  `v0.2` is not the point where Catalyst Continuum becomes a full MCP registry, package manager, or universal server catalog.

- `Duplication of native agent capabilities`
  Do not add control-plane abstractions for `git`, local filesystem access, or chat ergonomics when the real consumer value already lives inside the agent runtime.

- `Production MCP proxy deployment`
  Proxy-based deployment remains important, but it still comes after the direct `stdio` contract and interoperability checks are stable.
