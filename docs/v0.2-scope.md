# v0.2 Scope

This document defines the next cut line for Catalyst Continuum `v0.2`.

The former `v0.2` contract, interoperability, and operator-ergonomics batch was pulled forward and
absorbed into the closed `v0.1` boundary. That final `v0.1` cut is now tracked in
[v0.1-scope.md](v0.1-scope.md). LiteLLM's role as the designated AI edge gateway was also fixed in
the closed `v0.1` boundary, so later gateway work should extend that decision rather than redefining
it here.

The next concrete `v0.2` scope is runtime-provider expansion, execution hardening, and AI security
control-plane hardening. The dedicated security roadmap for that work lives in
[ai-security-roadmap.md](ai-security-roadmap.md).

## Planned For v0.2

- `Remote-ready workspace handoff` Carry task workspace state as a provider-neutral bundle alongside
  the current on-disk snapshot so future Proxmox and Kubernetes runtimes can hydrate the same input
  without relying on a local host mount contract. The first concrete slice of that work is the
  task-scoped `task_workspace_input` artifact, which persists the prepared workspace directory plus
  a pinned bundle manifest for external-agent and later remote-runtime handoff.

- `GitHub issue task brokering` Expand the current signed webhook and repository-signal foundation
  into a developer-facing queue that can import or receive GitHub issues, select a bounded next
  batch, materialize one issue at a time into a Catalyst run, and hand the resulting work package to
  Codex, OpenHands, Cursor, or another native coding agent without replacing that agent's UI.

- `Proxmox runtime-provider support` Add a Proxmox-backed runtime provider with linked-clone VM
  execution, Cloud-Init templates, and stronger isolation than the Docker-first baseline.

- `Kubernetes runtime-provider support` Add a Kubernetes-backed runtime provider using Jobs or Pods,
  with local validation via `kind` and the same control-plane contracts preserved across providers.

- `Execution isolation hardening` Keep tightening sandbox assumptions, rootless execution, and
  provider-neutral runtime boundaries as the system expands beyond Docker.

- `Run-scoped AI security envelope` Materialize a provider-neutral, inspectable security envelope
  per run so agents and operators can see the allowed MCP capabilities, egress assumptions, secret
  scope, and promotion constraints without reconstructing policy from scattered config.

- `Threat modeling and security backlog artifacts` Add a first threat-model artifact plus a derived
  security backlog artifact so prompt injection, tool abuse, exfiltration, and poisoning concerns
  become inspectable control-plane outputs rather than ad hoc notes.

- `Tainted context and provenance controls` Label inbound brief content, repository-derived content,
  GitHub payloads, and fetched external content with trust metadata so privileged actions cannot be
  driven directly from untrusted context without server-side validation.

- `AI security evaluations and telemetry` Add a pinned security-eval baseline for prompt injection,
  tool abuse, model abuse, and poisoning scenarios, and emit dedicated security events plus metrics
  into the existing OpenTelemetry and Grafana stack.

## Explicitly Out Of Scope For v0.2

- orchestrator-managed third-party MCP sidecar lifecycle
- generic MCP marketplace behavior
- duplication of native agent capabilities such as `git` or local filesystem access
- mandatory wrapping of native Codex, Cursor, or OpenHands interactive sessions
- production MCP proxy deployment as a required default
- broader agent-ecosystem expansion beyond the current control-plane delegation model
- replacing GitHub review with automated merge approval
- full enterprise identity, tenant isolation, or generic DLP platform work
