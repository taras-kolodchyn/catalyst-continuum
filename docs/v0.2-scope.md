# v0.2 Scope

This document defines the next cut line for Catalyst Continuum `v0.2`.

The former `v0.2` contract, interoperability, and operator-ergonomics batch was pulled forward and absorbed into the closed `v0.1` boundary.
That final `v0.1` cut is now tracked in [v0.1-scope.md](v0.1-scope.md).
LiteLLM's role as the designated AI edge gateway was also fixed in the closed `v0.1` boundary, so later gateway work should extend that decision rather than redefining it here.

The next concrete `v0.2` scope is runtime-provider expansion and execution hardening.

## Planned For v0.2

- `Remote-ready workspace handoff`
  Carry task workspace state as a provider-neutral bundle alongside the current on-disk snapshot so future Proxmox and Kubernetes runtimes can hydrate the same input without relying on a local host mount contract.
  The first concrete slice of that work is the task-scoped `task_workspace_input` artifact, which persists the prepared workspace directory plus a pinned bundle manifest for external-agent and later remote-runtime handoff.

- `Proxmox runtime-provider support`
  Add a Proxmox-backed runtime provider with linked-clone VM execution, Cloud-Init templates, and stronger isolation than the Docker-first baseline.

- `Kubernetes runtime-provider support`
  Add a Kubernetes-backed runtime provider using Jobs or Pods, with local validation via `kind` and the same control-plane contracts preserved across providers.

- `Execution isolation hardening`
  Keep tightening sandbox assumptions, rootless execution, and provider-neutral runtime boundaries as the system expands beyond Docker.

## Explicitly Out Of Scope For v0.2

- orchestrator-managed third-party MCP sidecar lifecycle
- generic MCP marketplace behavior
- duplication of native agent capabilities such as `git` or local filesystem access
- production MCP proxy deployment as a required default
- broader agent-ecosystem expansion beyond the current control-plane delegation model
